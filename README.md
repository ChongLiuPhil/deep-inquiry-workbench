# Deep Inquiry Workbench（深度探究工作台）

[中文](README.md) | [English](README.en.md)

一个由人导航、供不同 AI Agent 调用的深度探究工作流。它帮助任何人围绕重要、复杂或开放的问题，持续生成、检验和修正答案与理解，并把探究状态保存在可以本地打开的动态 Markdown 工作文档中。

它有两个紧密相连的作用：一是尽可能发挥 AI 的分析、检索、比较、核验和整理能力，实质推进人的探究；二是通过透明的证据判断、概念辨析、反例检验和方向选择，帮助人逐步提高语言判断与知识思考能力。教育作用融入真实探究，不取代探究本身。

它不要求用户先判断自己的问题属于人文、科学、技术、生活还是其他领域，也不依赖专用 UI。

## 核心定位

本项目把探究视为基本过程。

传统的“学习”常被想象为：知识已经以稳定答案存在，学习者只需吸收它。但既有知识本身是前人探究的阶段性成果；它可能带有范围、方法、证据和历史条件，也可能被修正。

因此，本工作流不把学习保留为与探究并列的独立流程。阅读、检索、记忆、练习、计算、实验和写作都在回答具体问题时自然发生，并服务于探究。这里持续生成和修正的是答案与理解；问题负责导航，问题的重大改变由人明确决定。

AI 在这个过程中是协助者：它可以生成候选想法、整理信息和帮助检查推理，但不是对等合作者、作者、事实权威或最终裁决者。人保留决定问题、先后顺序、方向转换、终止和采用结论的权利；本项目把这些权利简称为“导航权”。人也对最终使用的判断和行动承担责任。

## 两方面作用如何统一

本 Skill 首先是一个工程工具。它必须真实提高探究质量，而不能只向用户讲解方法。AI 应承担自己能够可靠完成的材料阅读、信息检索、结构整理、解释比较、反例寻找、计算核验和成果整合，把人的时间留给问题导航、价值选择和最终判断。

与此同时，工作流不会把思考过程藏在一段看似完整的答案后面。它会让主张依据、推理跳跃、概念边界、竞争解释、不确定性和方向选择保持可见。用户在真实问题中持续接触这些判断活动，语言判断力、证据意识和知识思考能力因而得到训练。

教育作用不是额外课程，也不是把每轮对话变成方法讲座。它融入实际探究并服务于探究；当教育性说明不能改变当前理解或行动时，不应挤占正文。

## 忠实执行：不偷懒，也不越界

本 Skill 把“精准可控”作为影响 Agent 行动的工程规则，而不只是沟通风格。AI 应像一辆动力充足、转向精准的车：人决定目的地和方向，AI 在划定范围内充分发挥能力。

- 目标清楚时，Agent 主动完成必要的阅读、分析、执行、核验和工作文档更新。
- “避免越界”不能成为少做必要工作的理由。
- “可能有帮助”也不能成为增加额外成果、功能、文件、重构、外部操作或相邻任务的理由。
- 会改变成果、主要目标、影响范围、成本、风险或外部状态的扩展，必须先交给用户决定。
- 用户纠正后，Agent 应把纠正吸收到后续行动中，而不是反复道歉、复述禁止项或列出无关的未做事项。

因此，忠实不是机械服从字面，也不是擅自替用户追求所谓“更完整”的结果；它是在人的目标和授权范围内，把能力用足，同时保持方向始终可由人准确控制。

## 它解决什么问题

普通聊天很容易出现三类断裂：

1. 回答按时间堆积，讨论越来越长，却没有形成可继续工作的结构。
2. AI 在后续回合忘记早期限定，或不知不觉改变了用户原来的问题。
3. 流畅表达、未经核验的信息、解释性判断和事实证据混在一起。

本 Skill 使用一个持续更新的 `workspace.md` 解决这些问题。文档按问题和主题组织，保存当前答案、理解、主张、证据、反例、被放弃路径、人类决定、下一步和交接状态。

## 核心能力

- **问题治理**：问题负责导航。AI 可以澄清措辞、缩小范围和拆出子问题，但改变核心问题必须由人明确决定。
- **答案与理解持续演进**：持续生成、检验和修正的是答案与理解；工作流不会为了表现进展而不断改写问题。
- **证据与说法分层**：区分事实、理论归属、解释、推测、价值判断和原创综合，并为不同说法采用相称的核验方法。
- **校准后的批判**：先善意重构，再按需要寻找最强反驳、反例、边界情况或竞争解释；批判是提高理解的工具，不是每轮仪式。
- **概念形成与检查**：只有新概念真正增加区分力、解释力或可操作性时才保留，并记录定义、边界、正反例和形成过程。
- **保存被放弃路径带来的认识**：记录一条路径为什么失败、它暴露了什么限制，以及什么条件可能使它值得重新开启，而不是只保存成功答案。
- **人类决定门槛**：核心问题、主要目标、价值取舍、风险接受和最终采用等决定必须由人完成；AI 不把沉默当成同意。
- **长程连续性**：状态写入本地工作文档，新会话或新 Agent 不依赖原聊天窗口即可接续。
- **精准可控的执行**：在用户划定的目标内充分发挥能力，不偷懒，也不擅自增加任务；用户纠正后自然吸收，不反复声明无关限制。

## 为什么不需要专用 UI

工作文档本身就是持久化界面：

- 它是普通 Markdown，可以用任何本地编辑器打开。
- 用户可以直接修改，Agent 再次写入前必须读取最新内容。
- 新会话或其他 Agent 可以只凭文档恢复探究状态。
- 每轮回复都会报告是否更新、更新了什么以及文档的绝对地址。
- 环境不可写时，Agent 必须明确报告失败并提供可恢复内容，不能假装保存成功。

支持本地文件链接的平台可以直接打开文档；其他平台仍可显示绝对路径。

## 默认采用通俗表达

本 Skill 默认假设人类参与者没有当前领域的专业背景。聊天回复、工作文档和最终成果都应优先使用普通、直接的语言。

- 能用普通词准确表达时，不使用行业黑话或学派术语。
- 必须使用专业术语时，在第一次出现处立即用日常语言解释。
- 缩写第一次出现时写出全称并说明用途。
- 不连续罗列多个领域的理论、人物和术语。
- 不用给现象贴标签来代替说明它怎样发生、有什么依据以及为什么相关。
- 先给能够直接理解的核心意思，再按需要补充精确细节和来源。

通俗表达不等于牺牲准确性。重要条件、例外、不确定性和反例仍然保留，只是避免把理解专业语言的额外负担交给用户。

## 适用范围

适合：

- 深入理解一个日常、社会、理论或实践问题。
- 比较多个竞争解释或解决方案。
- 围绕科学、技术、人文或跨学科问题进行研究。
- 把阅读、文献、数据或现有材料融入持续探究。
- 发展概念、检验论证、整理证据或形成报告。
- 需要跨会话、跨 Agent 保存状态的长期思考。

通常不需要触发：

- 一个简单事实已经足以回答的问题。
- 只需执行的明确操作。
- 一次性翻译、校对、格式调整或语言润色。
- 用户没有要求深入，也不会受益于持续状态记录的普通问答。

用户仍可在任何任务中显式调用本 Skill。

## 工作方式

### 首次启动

每个探究都是一个独立、本地可打开的项目。用户指定已有项目目录时直接使用；否则 Agent 在用户指定位置或当前工作区创建主题目录：

```text
<主题项目目录>/
├── workspace.md
├── materials/       # 按需保存用户要求纳入项目的材料
├── attachments/     # 按需保存较长的证据、检索、计算或实验记录
└── outputs/         # 按需保存报告、方案和成稿
```

`workspace.md` 直接位于项目根目录，其他目录只在出现实际内容时创建。Agent 生成的持久文件和后续更新都落在这个项目目录内。它把完整用户须知写入文档，在聊天中展示核心摘要并给出地址；用户明确回复“我确认知晓”或同等确认后，Agent 记录确认并开始实质探究。

首次须知不是普通免责声明。它让用户在开始前知道：AI 的流畅性不等于正确性；模型输出只是候选材料；AI 可能迎合既有立场或受到训练材料偏向的影响；人保留导航权和最终责任；工作流会主动暴露证据缺口、隐含前提、反例和不确定性。每个项目通常只需确认一次。

### 每个实质回合

Agent：

1. 读取工作文档恢复状态。
2. 核对当前目标、要求成果、允许影响的范围和需要另行确认的扩展。
3. 识别当前最关键的理解缺口。
4. 选择扩展最少、但能充分完成或核验目标的操作。
5. 生成或修正答案与理解。
6. 把持久变化整合进对应主题和稳定编号。
7. 更新修订号、交接摘要和简短变更日志。
8. 在回复末尾给出工作文档回执。

回执格式：

```text
工作文档
- 状态：已更新 / 无需更新 / 更新失败
- 本轮变化：revision 4；C-003 已修正；E-005 新增为待核
- 地址：/absolute/path/to/topic-project/workspace.md
```

“无需更新”是一种真实状态：纯确认、协议说明或没有形成持久变化的回答不会为了形式写入噪声。

## 文档模型

工作文档使用稳定编号：

| 前缀 | 对象 |
|---|---|
| `Q-` | 问题 |
| `C-` | 主张、候选答案或论点 |
| `E-` | 证据或来源记录 |
| `O-` | 反对意见、反例或竞争解释 |
| `N-` | 被放弃路径，以及从失败或放弃中得到的认识；简称“负向知识” |
| `D-` | 必须由人类作出的导航决定 |

问题与答案分开管理。核心问题通常保持稳定；答案、解释、证据状态和适用边界可以持续变化。重大问题重构需要建立 D- 条目并由用户明确决定。

“由谁或怎样提出”“现在是否保留”和“是否已经核实”也分开记录，避免把“AI 提出的”“已经保留的”和“已经核验的”误当成同一件事。

工作文档同时区分：

- **当前答案**：截至此刻，对核心问题最简洁、可辩护的回答。
- **当前理解**：支撑答案的机制、概念关系、证据、不确定性、竞争解释和适用边界。

答案可以暂时不存在，也可以保留多个竞争版本。没有足够证据时保持“待核”，不为得到一个完整结论而过早收敛。

## 证据与批判

本项目不要求对每句话机械反驳，也不要求每轮都以开放问题结尾。Agent 先善意重构，再根据当前瓶颈决定是否需要：

- 逻辑审计。
- 最强反驳或反例。
- 竞争解释比较。
- 概念辨析。
- 外部检索和证据核验。
- 思想实验、计算或测试。
- 路径裁剪或成果整合。

不同说法需要不同的检查方法。例如，事实和数字需要可靠来源；某位作者的观点要回到原文；解释要说明材料依据、推理、反例和适用范围；价值判断要说清价值前提。AI 的内部记忆、自信语气、多个模型给出相同回答或 AI 生成的参考文献，都不能直接当作证据。

工作流不强制固定研究阶段。每轮先判断当前缺口究竟是问题含混、概念不清、证据不足、解释竞争、逻辑断裂、价值取舍还是成果整合，再选择能够带来最大理解增量的少数操作。证据不可获得时应明确暂停相应结论，而不是用更多文字掩盖缺口。

## 文件结构

```text
deep-inquiry-workbench/
├── SKILL.md
├── README.md
├── README.en.md
├── LICENSE
├── NOTICE
├── CONTRIBUTING.md
└── resources/
    ├── user_guide.md
    └── workspace_template.md
```

- `SKILL.md`：Agent 可执行的完整决策协议。所有影响行为的关键规则都保留在这里。
- `README.md`：项目定位、使用方式和兼容说明。
- `README.en.md`：与中文主说明内容对应的英文版本。
- `resources/user_guide.md`：首次启动写入工作文档的完整用户须知。
- `resources/workspace_template.md`：权威工作文档模板。

V1 不依赖脚本。证据表、概念卡、反思和交接状态已经整合进一个主模板，不再要求维护多个平行活动文件。只有大块证据、检索记录、计算结果或成稿过长时才拆入附件。

## 安装与调用

将整个 `deep-inquiry-workbench` 目录安装到目标 Agent 支持的 Skills 目录。以 Codex 的常见本地配置为例：

```text
git clone https://github.com/ChongLiuPhil/deep-inquiry-workbench.git ~/.codex/skills/deep-inquiry-workbench
```

可以显式调用：

```text
$deep-inquiry-workbench 帮我探究：为什么……？
```

也可以使用自然语言：

```text
请不要只给一个答案，协助我系统探究这个问题，并持续记录我们的理解。
```

不同 Agent 对 Skill 自动发现、文件链接和写入权限的支持可能不同。完整体验需要 Agent 能读取 Skill 资源，并能在用户工作区创建和更新 Markdown 文件。

## 跨 Agent 接续

接手 Agent 应先读取 `workspace.md`，再核对与当前任务相关的原始条目。交接摘要只是状态快照，不能覆盖更详细的证据、限定和用户决定。

默认使用一个 Agent 连续推进。只有独立审计、角色隔离、可并行的清晰任务或用户明确要求时，才增加 Agent。多 Agent 的一致意见不是证据，也不按票数裁决。

## 两套原型的整合关系

本项目以 `conduct-humanities-ai-research` 中更成熟的工程骨架为基础：

- 主题式工作台。
- Q/C/E/O/N/D 稳定编号。
- 独立状态维度。
- 证据检查、必须由用户作出的决定、从失败路径中得到的认识，以及供新 Agent 接手的摘要。

同时吸收 `human-ai-research-os` 的关键贡献：

- 首次启动的元判断力须知。
- 对流畅性、迎合、偏见和上下文衰减的机制祛魅。
- 四类变化记录——确认、修正、AI 新增候选和用户反驳后深化——以及概念如何形成和改变、失败路径为何被放弃的记录。
- 将选择、修正和放弃视为高阶认知劳动。

整合时做了三项重要修正：

1. 从“人文学术研究”泛化为任何问题的探究。
2. 从“对等学术伙伴”改为由人导航、AI 协助的工具关系。
3. 从固定阶段、强制反驳和逐轮模板，改为由当前理解缺口驱动的动态工作流。

## 局限

- 没有写入权限时，Skill 只能生成待保存的结构化增量，无法真正维护本地状态。
- 工作文档能降低上下文衰减，但不能保证任何 Agent 都正确理解或执行协议。
- 证据质量仍取决于实际可访问的来源、工具、时间和核验方法。
- 对医疗、法律、金融、安全等高风险问题，工作流不能替代具备资质的人类专业判断。
- 公开可见不能从技术上阻止复制，也不能替代对侵权行为的法律追索；许可证只能明确权利边界。
